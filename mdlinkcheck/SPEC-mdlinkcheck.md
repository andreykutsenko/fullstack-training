# ТЗ: CLI-утилита проверки ссылок в Markdown

Реализуй полностью, без уточняющих вопросов. Неоднозначность — выбери вариант,
запиши в README, продолжай. В конце прогони `pytest` и покажи вывод.

## Стек

Python 3.11+. Зависимости: `markdown-it-py`, `httpx`, `rich`.
Для тестов: `pytest`, `respx`. Больше ничего не ставить.
`venv` + `requirements.txt`.

## Задача

1. Рекурсивно найти все `.md` файлы в указанной папке. Пропускать `.git`,
   `node_modules`, `.venv`, `__pycache__`.
2. Извлечь из них ссылки.
3. Проверить: локальные — что файл существует, внешние — что отвечает по HTTP.
4. Вывести таблицу в консоль: зелёным рабочие, красным сломанные.
5. Внизу строка вердикта: `Все ссылки рабочие: 142 из 142` либо
   `Сломанных ссылок: 7 из 142`.

## Вход

Позиционный аргумент — путь к папке. Если он начинается с `http`, это URL
репозитория GitHub: клонировать `git clone --depth 1` во временную папку,
сканировать её, удалить после. Форму `.../tree/main` понимать: `main` — ветка.

Перед вызовом git выставить в окружении `GIT_TERMINAL_PROMPT=0`, иначе на
приватном репозитории git запросит пароль и зависнет навсегда. Ошибка
клонирования — выход с кодом 2.

## Извлечение ссылок

Парсить через `markdown-it-py`, обходя токены. Регулярками по тексту не парсить —
иначе поймаешь ссылки внутри блоков кода, а их считать не надо.

```python
md = MarkdownIt("commonmark")
md.validateLink = lambda url: True   # ОБЯЗАТЕЛЬНО
```

Без второй строки markdown-it молча выбрасывает `file://` ссылки — они просто не
появятся в результате. Проверено.

Брать `href` из токенов `link_open` и `src` из токенов `image`. Этого достаточно:
markdown-it сам разворачивает референсные ссылки `[a][ref]` и автоссылки
`<https://...>` в те же токены.

Голые URL в тексте, не оформленные как ссылка, не ищем.

Для каждой ссылки запомнить путь файла, в котором она найдена, и номер строки
(`map[0]+1` у родительского блочного токена).

## Проверка

**Локальные.** Отбросить `#якорь` и `?query`, декодировать `unquote`.
Резолвить **от папки того файла, где ссылка найдена** — не от текущей
директории и не от корня. Файл или папка существует → OK, нет → BROKEN.

Схема `file://` — отдельный случай: это абсолютный путь ОС, получать его через
`urllib.request.url2pathname`, а не резолвить относительно чего-либо.

**Внешние.** `httpx`, таймаут 10 секунд, редиректы разрешены.

Сначала `HEAD`. **Если код ответа ≥ 400 — повторить как `GET`** и взять его
результат. Именно по коду, а не «если ответа нет»: многие серверы штатно
отвечают на HEAD кодом 405 или 403, и это ответ, а не его отсутствие.

Заголовок `User-Agent` поставить браузерный — дефолтный UA httpx блокируется
Cloudflare и GitHub с кодом 403.

Итог: 2xx/3xx → OK. 4xx/5xx → BROKEN с кодом. Таймаут или ошибка сети → BROKEN.

Одинаковые URL запрашивать один раз. Запросы слать параллельно, не более 10
одновременно, иначе сотня ссылок по 10 секунд превратится в минуты.

Схемы `mailto:`, `tel:` и чистые `#якоря` пропускать со статусом SKIPPED.
Их нет в знаменателе вердикта.

## Вывод

`rich.table.Table`, колонки: файл, строка, ссылка, статус, HTTP-код, примечание.
Цвет отключать, если stdout не терминал.

## CLI

```
mdlinkcheck <путь-или-URL> [--broken-only] [--report FILE] [--timeout N]
```

`--report FILE` — записать сломанные ссылки в markdown-файл. Создавать его даже
если сломанных нет, с явной пометкой об этом: отсутствие файла и «всё хорошо»
не должны выглядеть одинаково.

Коды возврата: 0 — сломанных нет, 1 — есть, 2 — ошибка (путь не найден,
клон не удался, нет прав).

## Тесты

`pytest`, сеть мокать через `respx`. Фикстура — папка с заведомо битыми ссылками.

1. `[a](./file.md)`, `[a][ref]`, `<https://x.com>`, `![img](./p.png)` — все найдены.
2. Ссылка внутри блока ``` — не найдена.
3. `[a](file:///tmp/x.md)` — найдена (регрессия на `validateLink`).
4. `../sibling.md` резолвится от файла-источника, а не от cwd.
5. Несуществующий файл → BROKEN.
6. HEAD 405 → GET 200 → OK, ровно два запроса.
7. HEAD 404 → BROKEN.
8. Таймаут → BROKEN.
9. Один URL трижды → один сетевой запрос.
10. Есть сломанные → exit 1, нет → exit 0.

## Готово, когда

- `pip install -r requirements.txt` проходит
- `pytest` зелёный, сеть не дёргается
- `python -m mdlinkcheck ./tests/fixtures` печатает таблицу и вердикт
- `python -m mdlinkcheck <папка> --report broken.md` создаёт файл
- `echo $?` даёт 1 при наличии сломанных
- есть README с инструкцией запуска
